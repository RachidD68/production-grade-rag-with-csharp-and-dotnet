# 0014 — Upgrade MAF from 1.13.0 to 1.14.0 (post-ship maintenance pass, July 2026)

Date: 2026-07-22

## Status

Accepted (supersedes ADR-0013, which remains the record of the 1.11.1 → 1.13.0
bump).

## Context

Microsoft released **MAF `dotnet-1.14.0`** on 2026-07-21, one day after this
book's manuscript was finalized on `1.13.0`. A reader running
`dotnet add package Microsoft.Agents.AI` now resolves `1.14.0`, so the baseline
moves before the book reaches print — the same first-day-old-on-the-shelf drift
ADR-0010 through 0013 guarded against.

`1.14.0` is a **graduation release**: the human-in-the-loop surface came out of
experimental. `ToolApprovalAgent` went GA, message injection
(`EnableMessageInjection`, `UseMessageInjection()`, `MessageInjectingChatClient`)
dropped `[Experimental("MAAI001")]`, and `HarnessAgent`, `FileMemoryProvider`
and the todo/agent-mode providers graduated alongside them. Three changes are
flagged breaking upstream:

1. **Auto-approval rules take a context object.** Rules now receive a
   `ToolAutoApprovalRuleContext` (read `context.FunctionCallContent`) rather than
   a raw `FunctionCallContent`. **SmartDocs defines no custom auto-approval
   rules**, so nothing here changes.
2. **Approval responses bind to surfaced requests.** An approval is honored only
   when matched, one-time, to a framework-issued request id held in session
   state; `ChatClientAgentOptions.DisableApprovalResponseBinding` opts out.
   `samples/Ch23_HumanInTheLoopApproval` was audited against this: it calls
   `request.CreateResponse(...)` on a request the framework surfaced and replays
   it on the **same session**, which is exactly the pattern the change requires.
   No change needed.
3. **Message injection graduation** is attribute-only — nothing renamed, no
   behavior change. `IChatMessageInjector` and `MessageAIContextProvider` remain
   two distinct primitives (mid-loop injection vs. context before the first
   turn); 1.14 did not merge them.

Also in the wave, but untouched by this codebase: `Workflow.AsAIAgent()` now
honors terminal workflow outputs, a message-ordering fix in workflow-hosted
agents, a `MessageMerger` refactor, the first `Microsoft.Agents.AI.Valkey`
package, and a `CosmosNoSql` TTL fix.

## Decision

Pin to the latest stable patch:

- `Microsoft.Agents.AI` / `.Abstractions` / `.OpenAI` / `.Workflows` → **`1.14.0`**.
- `Microsoft.Agents.AI.Foundry` / `.A2A` / `.Hosting.A2A.AspNetCore` →
  **`1.14.0-preview.260721.1`** (still preview-only at the 1.14 milestone).
- `Microsoft.Agents.AI.Mem0` stays **`1.0.0-preview.251028.1`** (its own line).

`Microsoft.Extensions.AI*` / `…VectorData.Abstractions` stay at **`10.7.0`**: the
`1.14.0` nuspec still declares a `Microsoft.Extensions.AI` floor of **`10.6.0`**,
which `10.7.0` already satisfies. Every other pin — database drivers, the
`10.0.9` platform cohort, `ModelContextProtocol 1.4.0`, the `Microsoft.OpenApi
2.7.5` audit pin — stays put.

## Consequences

- **No production-code changes.** `1.13.0 → 1.14.0` is a clean drop-in:
  `dotnet build` is 0 warnings / 0 errors (warnings-as-errors) with zero source
  edits, and the full suite passes — **443 tests** (361 unit + 67 security +
  15 integration; 1 skipped, the ONNX real-model test).
- **No approval-flow migration.** The one place this codebase touches the
  approval surface (Ch23) was already written against surfaced requests, so the
  #7111 binding change is a no-op here. Readers upgrading a **serialized session
  with an approval still pending** are not so lucky — that approval is ignored
  after the upgrade and the request must be re-issued. This is now an entry in
  Appendix G, and `DisableApprovalResponseBinding` was confirmed present in the
  shipped assembly before the book named it.
- **Book baseline.** Install-baseline version strings move `1.13.0 → 1.14.0` and
  the Ch02 "what's new" list gains a `1.14.0` clause. Historical "introduced in
  1.4.x–1.13" notes are left untouched, as are the M.E.AI `10.7.0` strings and
  the "floor stays 10.6.0" sentence — both still accurate.
