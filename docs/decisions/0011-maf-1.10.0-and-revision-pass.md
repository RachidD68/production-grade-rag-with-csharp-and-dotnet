# 0011 — Upgrade MAF from 1.8.0 to 1.10.0 (final pre-publish pass, June 2026)

Date: 2026-06-21

## Status

Accepted

## Context

Microsoft released **MAF `dotnet-1.10.0`** on June 10, 2026. This is the final
package reconciliation before the book ships. The companion code and book text
were last pinned to **`1.8.0`** (June 2, 2026, see ADR-0010). The window
between the two releases spans one intermediate minor — `1.9.0` (June 3) — and
its main themes are the de-experimentalisation of the .NET orchestrations and
the promotion of the declarative-workflow surface to stable.

Shipping a 2026 book at `1.8.0` while readers' first `dotnet add package`
resolves to `1.10.0` is the same first-day-old-on-the-shelf drift ADR-0010
guarded against, so the baseline moves to `1.10.0`.

This bump also paired the `Microsoft.Extensions.AI` family up to **`10.7.0`**,
which is where the real work of this upgrade lived (see *Transitive floors*).

### Breaking changes between 1.8.0 → 1.10.0

Verified against this codebase via `grep` over `src/`, `tests/`, `samples/`,
and the chapter `render.js` sources, plus a clean warnings-as-errors build.

| # | Release | Breaking change | Impact here |
|---|---|---|---|
| 1 | `1.9.0` | `[Experimental]` removed from the .NET Orchestrations (PR #6164); the agent-orchestration types are now stable API | None — and a small net positive. The codebase carries **zero** `#pragma warning disable` suppressions for the orchestration experimental diagnostics (grep: 0 hits for `Orchestration`, `Experimental`, `pragma warning`), so nothing needs unsuppressing. |
| 2 | `1.9.0` | `Microsoft.Agents.AI.Workflows.Declarative` promoted from preview to stable | None — Ch 19 uses the programmatic `Workflow` builder, not the declarative/YAML surface. |
| 3 | `1.10.0` | Magentic orchestration now shares participant replies with the manager by default (behaviour fix) | None at the API level — the two files referencing `Magentic`/`RunMagenticAsync` compile and their tests pass unchanged. (The `RunMagenticAsync` → `RunAgentsAsToolsAsync` rename is a *book-clarity* change tracked separately in the Ch 19 revision, not a framework break.) |
| 4 | `1.10.0` | GitHub Copilot agent SDK migration + hosting fixes | None — the lone `Copilot` reference is descriptive prose in a sample, not an SDK call. |

The carry-over OpenTelemetry caveat from earlier bumps no longer applies in the
form ADR-0010 stated it (see *Corrections to the record* below).

### Transitive floors (the substance of this bump)

`Microsoft.Extensions.AI 10.7.0` raised two floors that the previous `10.5.1`
pin did not impose. These surfaced as `NU1109` package-downgrade errors on
first restore and were resolved by bumping the existing central pins (no new
packages, no STOP-gate):

- `Microsoft.Extensions.AI.OpenAI 10.7.0` → `OpenAI (>= 2.11.0)`. The repo pinned
  `OpenAI 2.10.0`; bumped to **`2.11.0`** (latest 2.x).
- `Microsoft.Extensions.AI 10.7.0` → `Microsoft.Extensions.DependencyInjection.Abstractions`
  and `Microsoft.Extensions.Logging.Abstractions (>= 10.0.9)`. The repo pinned the
  whole .NET 10 platform cohort at `10.0.7`; moved the entire cohort
  (`Microsoft.Extensions.*`, `Microsoft.AspNetCore.*`, `Microsoft.Bcl.Memory`) to
  **`10.0.9`** to keep the servicing band coherent — `10.0.9` is the latest
  10.0.x servicing release, so this is "bump to latest patch", not just
  "satisfy the floor".

### Corrections to the record (ADR-0010)

Two pre-existing pins were verified against NuGet during this pass and corrected:

- **`Microsoft.Agents.AI.OpenTelemetry` does not exist on NuGet.** A query for
  `packageid:Microsoft.Agents.AI.OpenTelemetry` returns `totalHits: 0`; the
  flat-container index `404`s. ADR-0010 pinned it to `1.8.0` and described an
  "auto-wires the underlying IChatClient" behaviour, but the pin only ever
  survived because **no project references it** (Central Package Management
  silently ignores a pin with no consumer). The pin is **removed**. MAF agent
  telemetry comes from `Microsoft.Agents.AI` core + `Microsoft.Extensions.AI`'s
  `OpenTelemetryChatClient`, exported with the already-pinned `OpenTelemetry.*`
  packages — there is no separate MAF OpenTelemetry SKU to reference.
- **`Microsoft.Agents.AI.Foundry` has no `1.10.0` GA** (GA stops at `1.5.0`;
  `1.6.0+` are preview-only). The prior `1.8.0` pin also referenced a
  non-existent GA and likewise survived only because no project consumes it.
  It now tracks the matching **`1.10.0-preview.260610.1`** so the Ch 6/14
  Foundry samples resolve a real version if enabled, consistent with the A2A
  preview pins.

## Decision

Pin the stable MAF packages to **`1.10.0`**, the Foundry/A2A preview packages to
**`1.10.0-preview.260610.1`**, the `Microsoft.Extensions.AI` family to
**`10.7.0`**, and the .NET 10 platform cohort to **`10.0.9`** in
`Directory.Packages.props`. Remove the phantom `Microsoft.Agents.AI.OpenTelemetry`
pin.

```xml
<PackageVersion Include="Microsoft.Agents.AI" Version="1.10.0" />
<PackageVersion Include="Microsoft.Agents.AI.Abstractions" Version="1.10.0" />
<PackageVersion Include="Microsoft.Agents.AI.OpenAI" Version="1.10.0" />
<PackageVersion Include="Microsoft.Agents.AI.Workflows" Version="1.10.0" />
<PackageVersion Include="Microsoft.Agents.AI.Foundry" Version="1.10.0-preview.260610.1" />
<PackageVersion Include="Microsoft.Agents.AI.A2A" Version="1.10.0-preview.260610.1" />
<PackageVersion Include="Microsoft.Agents.AI.Hosting.A2A.AspNetCore" Version="1.10.0-preview.260610.1" />
<!-- no Microsoft.Agents.AI.OpenTelemetry pin: the package does not exist -->
<PackageVersion Include="Microsoft.Extensions.AI" Version="10.7.0" />
<PackageVersion Include="OpenAI" Version="2.11.0" />
<!-- Microsoft.Extensions.* / Microsoft.AspNetCore.* / Microsoft.Bcl.Memory → 10.0.9 -->
```

The only source change this bump entails is documentary: three XML-doc comments
in `src/SmartDocs.Agents/SmartDocsAgent.cs` referenced "MAF 1.6.1" as the
install baseline. They are reframed — the install-baseline mention moves to
`1.10.0`, and the two "equivalent of the MAF 1.6.1 `IChatMessageInjector`"
phrasings become version-agnostic ("MAF's `IChatMessageInjector`"), since that
hook exists across 1.6.1 → 1.10.0 and the equivalence is not version-specific.

The book text bumps in sibling commits during the per-chapter revision pass.

## Consequences

**Positive**:
- Readers running `dotnet add package Microsoft.Agents.AI` at publication resolve
  to the same `1.10.0` the book describes.
- The book picks up real surfaces (stable orchestrations, stable declarative
  workflows, `ToolApprovalAgent` HITL) as additive callouts with no reader-facing
  code rewrite.
- Two latent landmines are removed from `Directory.Packages.props`: a pin to a
  non-existent package id, and a pin to a non-existent Foundry GA. Both would
  have failed restore the instant a reader added a `PackageReference` for them.
- The .NET 10 platform cohort is aligned at the latest `10.0.9` servicing patch.

**Negative / accepted trade-off**:
- The A2A and Foundry SKUs remain preview at the `1.10.0` milestone — unchanged
  risk profile from `1.8.0`, where they were already on preview suffixes.
