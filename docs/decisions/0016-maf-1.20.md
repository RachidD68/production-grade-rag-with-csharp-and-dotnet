# 0016 — Upgrade MAF from 1.16.0 to 1.20.0, MCP SDK 1.4.0 to 2.2.0, retire gpt-4o (September 2026)

Date: 2026-09-05

## Status

Accepted (supersedes ADR-0015, which remains the record of the 1.14.0 → 1.16.0
bump — with one correction to it, recorded below).

## Context

Microsoft shipped four MAF releases after 1.16.0: **`dotnet-1.17.0`**
(2026-08-04), **`1.18.0`** (2026-08-18), **`1.19.0`** (2026-08-22) and
**`1.20.0`** (2026-08-31). A reader running `dotnet add package
Microsoft.Agents.AI` resolves 1.20.0. Two other things moved underneath the
book in the same window and are handled in this pass because they are the ones
that actually break a reader:

1. **The Model Context Protocol revision of 2026-07-28**, implemented by the
   C# SDK **2.x**. The protocol is now stateless by default: the
   `initialize` / `notifications/initialized` handshake is replaced by
   `server/discover`, the protocol version and capabilities travel in a `_meta`
   envelope on every request, `Mcp-Session-Id` / `Last-Event-ID` and the
   standalone GET stream are gone, roots / sampling / logging are deprecated
   (12-month window), and elicitation becomes a multi-round-trip request
   (`resultType: "input_required"`). Chapter 18 taught the old handshake.
2. **`gpt-4o` and `gpt-4o-mini` are Deprecated on Azure OpenAI** — no new
   deployments — so `deploy/main.bicep` could no longer be deployed fresh.

### MAF 1.17.0 – 1.20.0, what reaches this codebase

None of the four releases deprecates or removes an API this repository uses.
`ChatClientAgent`, `AIContextProvider`, `AgentSession`, the Workflows graph
API and the tool-approval surface are unchanged.

- **1.17.0** moved DurableTask / Azure Functions hosting to the separate
  `microsoft/agent-framework-durable-extension` repository (not used here) and
  made declarative workflows fail on an agent error instead of continuing.
- **1.18.0** — `ToolApprovalAgentOptions.MaxAutoApprovalIterations` (default
  10; Ch 23 documents the cap), `BackgroundAgentsProvider.ReleaseSessionAsync`,
  a Cosmos DB chat-history + vector-memory sample, opt-in concurrent tool
  execution, and **token usage aggregated across the whole agent loop**.
  SmartDocs meters at the `IChatClient` level (`CostMeter`), below the agent,
  so its numbers are unaffected. One rename is confined to the Hosting preview
  package (`SessionIsolationKeyProvider` → `AgentIsolationKeyProvider`, 0
  usages here).
- **1.19.0** — `RoutePersistingRoutingChatClient`, the
  `AzureBlobAgentSessionStore` preview, an alpha AgentHooks surface, the
  `Microsoft.Extensions.AI` floor raised to **10.9.0**, and a Tasks rename in
  the alpha `Microsoft.Agents.AI.Mcp` package (not referenced).
- **1.20.0** — `Microsoft.Agents.AI.Harness` stable (`AsHarnessAgent()`),
  public-API analyzers, `ChatOptions.Reasoning`, the
  `Microsoft.Extensions.VectorData.Abstractions` floor raised to **10.8.2**,
  and `CommunityToolkit.VectorData.CosmosNoSql` renamed to
  `…AzureCosmosDB` (not referenced).

### Correction to ADR-0015

ADR-0015 states that the 1.16 A2A adapter fix "reaches this codebase, since
Ch18/Ch25 pin `Microsoft.Agents.AI.Hosting.A2A.AspNetCore`". **No project
references that package** (nor `.Foundry` or `.A2A`); the three are
version-coherence pins in `Directory.Packages.props` only, kept so a reader who
adds one gets the matching milestone. The fix was therefore not inherited.

## Decision

- `Microsoft.Agents.AI` / `.Abstractions` / `.OpenAI` / `.Workflows` → **1.20.0**.
- `Microsoft.Agents.AI.Foundry` / `.A2A` / `.Hosting.A2A.AspNetCore` →
  **1.20.0-preview.260831.1** (coherence pins, see above). `.Mem0` stays
  `1.0.0-preview.251028.1`.
- `Microsoft.Extensions.AI` / `.Abstractions` / `.OpenAI` → **10.9.0**;
  `Microsoft.Extensions.AI.Evaluation` / `.Quality` / `.Reporting` → 10.9.0;
  `.Safety` / `.NLP` → `10.9.0-preview.1.26411.16` (the only 10.9 ids published
  for those two).
- `Microsoft.Extensions.VectorData.Abstractions` → **10.8.2**.
- `OpenAI` → **2.12.0**, `Azure.AI.OpenAI` stays 2.1.0.
  `Microsoft.Extensions.AI.OpenAI` 10.9.0 caps the OpenAI SDK at 2.12.x, so the
  cap is recorded next to the pin.
- The `Microsoft.Extensions.*` platform cohort (Hosting, DI, Configuration,
  Logging, Options, Http, Caching, `Microsoft.Bcl.Memory`, the AspNetCore
  OpenApi / Mvc.Testing / JwtBearer pins — 21 entries) **10.0.9 → 10.0.11**:
  MEAI 10.9.0 / MAF 1.20.0 require ≥ 10.0.11 and restore fails with NU1109
  otherwise. `Microsoft.Bcl.Memory` is still pulled in by
  `Microsoft.ML.Tokenizers.Data.{Cl100kBase,O200kBase} >= 9.0.4`; only the
  pinned value moved.
- `ModelContextProtocol` / `.Core` / `.AspNetCore` → **2.2.0** (`.Core` now
  pinned explicitly). Requires `Microsoft.Extensions.AI.Abstractions >= 10.8.3`,
  satisfied by the 10.9.0 pins.
- `deploy/modules/openai.bicep` deploys **`gpt-5.6-terra`** (deployment `chat`,
  output `chatDeployment`) with `model.version` omitted — the ARM contract
  documents it as optional and assigns the platform default, and this repo
  cannot verify a dated gpt-5.6-terra version offline — and
  `versionUpgradeOption: OnceNewDefaultVersionAvailable`.
  `SmartDocs__Llm__ChatModel` follows. The mapping used across the book is
  gpt-4o → gpt-5.6-terra, gpt-4o-mini → gpt-5.6-luna, gpt-4.1 → gpt-5.6-sol.

## Consequences

- **One source change for MCP.** `Ch18_McpHttpServer` now configures
  `WithHttpTransport(o => o.SessionMode = HttpServerSessionMode.Stateless)`;
  the SDK still exposes the boolean `Stateless`, but `SessionMode`
  (`Stateless` / `Stateful` / `StatefulForInitializeClients`) is the surface
  that matches the spec, and `Stateful` is now only needed for
  `subscriptions/listen`. The MCP smoke test additionally asserts
  `McpClient.ServerInfo` (populated by `server/discover`) before `tools/list`.
  The Ch18 stdio client comments mark `HttpTransportMode.Sse` as legacy.
- **No other production-code change.** `dotnet build` is 0 warnings / 0 errors
  with warnings-as-errors; the suite passes — **458 tests** (372 unit + 71
  security + 15 integration; 1 skipped, the ONNX real-model test), the same
  count as ADR-0015.
- **Ch21 AOT sample.** `dotnet publish -p:PublishTrimmed=true` runs ILLink over
  the closure and emits **zero `IL` warnings** on MCP 2.2.0 + MEAI 10.9.0.
  `-p:PublishAot=true` on a machine without the C++ workload stops at the
  linker prerequisite check (`SetupOSSpecificProps`) before ILC starts, so no
  ILC-level observation exists; the sample keeps `TreatWarningsAsErrors=false`
  as a safety net, and its README says so.
- **Ch24 model card.** The offline `StubModelRegistry` keeps the dated,
  now-retired `gpt-4o` / `2024-11-20` record on purpose: a model card must keep
  recording what *was* deployed after the model is retired, and a real
  `IModelRegistry` reads name and version from the live deployment.
- **Left alone, deliberately.** ADR-0008 (history); the tokenizer-lineage
  comments (`o200k_base` is unchanged for the gpt-5.6 family); test-fixture
  literals; the `gpt-4o-transcribe` / `gpt-4o-mini-transcribe` / `-tts`
  **audio** model ids, which sit on their own lifecycle and must never be
  blanket-replaced. A pre-existing `az bicep build` error (BCP181,
  `deploy/main.bicep(220,37)`, `listKeys` on Application Insights) is unrelated
  to this pass; the `deploy-prod` workflow is not live (no Azure credentials).
- **Book baseline.** Install-baseline strings move 1.16.0 → 1.20.0, MEAI
  10.7.0 → 10.9.0, VectorData → 10.8.2, MCP 1.4.0 → 2.2.0, the platform cohort
  10.0.9 → 10.0.11; Chapter 18 is rewritten for the 2026-07-28 protocol; the
  gpt-4o mentions become gpt-5.6-terra / -luna where instructional and are
  labelled as the historical baseline where they anchor measured numbers
  (Ch 10 latency, Ch 20 cross-judge, Ch 21 cost bands). Historical statements
  (the version-history narrative, ADR-0015's own text) are left untouched.
