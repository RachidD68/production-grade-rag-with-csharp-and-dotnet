# 0015 — Upgrade MAF from 1.14.0 to 1.16.0 (pre-print maintenance pass, July 2026)

Date: 2026-08-02

## Status

Accepted (supersedes ADR-0014, which remains the record of the 1.13.0 → 1.14.0
bump).

## Context

Microsoft released **MAF `dotnet-1.15.0`** on 2026-07-22 and **`dotnet-1.16.0`**
on 2026-07-30. A reader running `dotnet add package Microsoft.Agents.AI` now
resolves `1.16.0`, so the baseline moves again before the print run — the same
first-day-old-on-the-shelf drift ADR-0010 through 0014 guarded against. This
pass covers both releases.

**1.15.0** carries the wave's only breaking change, and it does not reach this
codebase:

1. **Hosting OpenAI Responses protocol helpers** (upstream #7000, `[BREAKING]`):
   `AgentSessionStore` in the `Microsoft.Agents.AI.Hosting` preview package
   gains an abstract `DeleteSessionAsync()` and renames its store-id parameter
   to `sessionStoreId`. Only custom `AgentSessionStore` subclasses are affected.
   **SmartDocs neither references `Microsoft.Agents.AI.Hosting` nor subclasses
   `AgentSessionStore`** (the one Hosting-family pin here is
   `.Hosting.A2A.AspNetCore`, a different package), so nothing changes.
   The rest of that PR is additive: an `OpenAIResponses` facade,
   `HostedWorkflowState` / `HostedAgentState`, with `MapOpenAIResponses` and
   `IResponsesService` untouched.

Also in 1.15.0, untouched by this codebase: a Dapr-as-agent-provider
GettingStarted sample, a declarative-autosend output fix, an expensive-logging
fix, and two workflow-credential hardening changes. The `Microsoft.Extensions.AI`
floor stayed `10.6.0`.

**1.16.0** is additive throughout — no breaking changes, no deprecations:

- The **GitHub Copilot agent graduated to stable** (not used here).
- New samples upstream: `TodoProvider`, `AgentModeProvider`, GitHub Copilot
  BYOK, `FileMemoryProvider` under AgentWithMemory, source-ZIP hosted-agent
  deploys. `Microsoft.Agents.AI.LocalCodeAct` joined the release solution filter.
- **A2A adapter now forwards `MessageSendParams.Configuration`** — the one fix
  this codebase actually inherits, since Ch18/Ch25 pin
  `Microsoft.Agents.AI.Hosting.A2A.AspNetCore`. Configuration set by a calling
  agent is no longer dropped at the adapter boundary.
- `InMemoryChatHistoryProvider` no longer double-persists when the service
  stores history (not used here — SmartDocs has its own providers).
- The `Microsoft.Extensions.AI` floor moved to **`10.7.0`**, which this
  repository has pinned since the 1.13 pass.

Neither release documents a single deprecated or `[Obsolete]`-marked API.

## Decision

Pin to the latest stable patch:

- `Microsoft.Agents.AI` / `.Abstractions` / `.OpenAI` / `.Workflows` → **`1.16.0`**.
- `Microsoft.Agents.AI.Foundry` / `.A2A` / `.Hosting.A2A.AspNetCore` →
  **`1.16.0-preview.260730.1`** (all three still preview-only at the 1.16
  milestone).
- `Microsoft.Agents.AI.Mem0` stays **`1.0.0-preview.251028.1`** (its own line).

`Microsoft.Extensions.AI*` / `…VectorData.Abstractions` stay at **`10.7.0`** —
now exactly the declared floor rather than above it. Every other pin stays put.

## Consequences

- **No production-code changes.** `1.14.0 → 1.16.0` is a clean drop-in:
  `dotnet build` is 0 warnings / 0 errors (warnings-as-errors) with zero source
  edits, and the full suite passes — **458 tests** (372 unit + 71 security +
  15 integration; 1 skipped, the ONNX real-model test).
- **A2A behavior improves silently.** Callers of the Ch18 A2A endpoint that set
  `MessageSendParams.Configuration` now have it honored. No SmartDocs test
  asserted the old (dropped) behavior, so nothing needed updating.
- **Book baseline.** Install-baseline version strings move `1.14.0 → 1.16.0`.
  Historical statements ("1.14.0 released 2026-07-21", the version-history
  narrative) are left untouched, as is the M.E.AI `10.7.0` pin — the floor
  sentence changes from "floor stays 10.6.0" to "floor is 10.7.0 as of 1.16.0"
  where the book states it as current fact.
